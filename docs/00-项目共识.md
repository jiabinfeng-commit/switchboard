## 一句话

在 GLPI 之上做一层 AI 服务台：员工对话、工程师 Copilot、评测看板；自研业务流程编排引擎 + Agent 运行时；GLPI 仍是工单、资产、SLA、KB 的系统 of record。

## 场景

企业 IT 服务台，参照 5 万人规模：每人一台电脑、一个账号。报障包括电脑故障、装软件、开权限、网络不通、显示器不亮。需求包括资产台账、工单流转、知识库自助、SLA 考核。

## 这个项目为了什么

- 练习 agent 设计与流程编排，同时作为求职作品。
- 起点是工程师思维：给明确需求能实现，从零设计时容易没思路。目标是把「怎么设计」
  变成能复述、能迁移的方法，而不只是产出一个能跑的系统。
- 要练的能力：拆步骤、定义每步的输入输出与失败语义、判断哪些交给模型哪些必须交给
  规则代码、验证与回放。
- 协作方式：代码由 Claude 写，设计判断由我拍板；每条切片停下来验收，
  我必须能用自己的话解释逻辑。
- 节奏：每天约 5 小时。宁可慢，也不要出现「能跑但说不清为什么」的东西。

## 三层架构

- 入口层：员工对话 / 工程师 Copilot / 运维与评测看板
- 智能层：业务流程编排引擎 + Agent 运行时 + 知识引擎 + 证据校验 + 评测
- 记录层：GLPI 11.x（Docker + MariaDB）
- 防腐层：TicketBackend / AssetBackend / KnowledgeBackend；GlpiAdapter + FakeAdapter

## 编排分两层

1. 业务流程编排（自研）：状态机、持久化、定时器、人工任务、重试、幂等、补偿、版本、事件日志与回放。管跨小时/跨天的流程。
2. Agent 编排：规划、工具调用、证据校验、策略、记忆。只负责单个步骤内部。LangGraph 可以用在这一层，隔离在 AgentRuntime 接口后。


## GLPI 边界

GLPI 负责：

- 工单创建、状态流转、跟进、解决方案
- 资产台账、人与资产绑定
- 用户、组织、实体、profile
- 优先级计算、SLA 时钟、升级
- 分类/派组规则（RuleTicket）
- KB 存储、版本、发布
- 通知、报表

我们负责：

- 员工对话、多轮澄清
- KB 与历史工单的语义检索、混合检索、重排、chunk 级引用
- 工单质量评估、语义查重
- 回答的事实校验
- 业务流程编排与 Agent 运行时
- 评测、轨迹、回放
- 员工聊天入口、工程师 Copilot、运维看板

不重写 GLPI 的 SLA、RuleTicket、审批记录。审批若属于工单，用 GLPI validation。

## 五条边界

1. 单一写者：工单/SLA/派单归 GLPI；会话/索引/评测归我们。
2. 规则裁决，模型提取：模型产出分类、紧急度、影响度、资产；GLPI 规则算优先级、SLA、派组。冲突记录，不静默覆盖。
3. 权限双保险：GLPI 侧受限账号或用户级 OAuth；我们侧强制请求人=当前登录人，user_id 不进模型参数。权限过滤在检索前。
4. 不 fork GLPI：只通过 API 扩展，不改 PHP 核心。
5. 人在环分级：建单确认；派单/改优先级按策略；关单和 KB 发布必须人工。

## 知识引擎（RAG）

三类知识：

- GLPI KB：策展、权威、量小
- 已解决工单 + 解决方案 + 跟进：经验、量大、质量参差
- SOP / 厂商文档：规程、最权威、更新慢

设计：

- 结构化事实（资产、软件版本、SLA 余额）走工具，不进向量库
- 混合检索：BM25 + 向量 + 元数据过滤 + 重排
- 引用到 chunk：标题 + 小节 + 更新时间 + 链接
- 权限过滤在检索前（entity/profile ACL 进索引元数据）
- 新鲜度：增量同步、过期标记、适用版本
- 反馈闭环：解决/未解决、工单结果、知识缺口

## 技术选型

- Python + FastAPI；Postgres 存流程实例/步骤执行/事件日志
- GLPI 锁 11.0.x（12.0.0 于 2026-10-07 发布，刚一个月，API v3 和 KB 重写，暂不押；等 12.0.1/12.0.2）
- Docker：官方 glpi/glpi 镜像有 arm64，macOS 可直接跑
- Agent 层可用 LangGraph；workflow 层自研
- 评测：ScriptedChatModel + 真实模型两套；轨迹回放
- 参考 tclkb 的模式（工具信封、verify、metrics/replay），不 import 业务代码

## 不做

- 不替换 GLPI 的 UI、认证、SLA、报表、通知
- 不做通用聊天机器人
- 不做无人值守自动关单
- 不做 CMMS
- 不做纯 RAG demo
